# 网络技术综合实习实验报告：LLM应用的提示注入攻防实验

**实习方向**：方向三 网络安全智能化  
**对应选题**：选题6 LLM应用的提示注入攻防实验  
**对应教材**：谢希仁《计算机网络》（第8版）第 7 章 网络安全  

---

## 摘要

随着大型语言模型（LLM）被广泛集成至现代网络应用架构（LLM-as-a-Service）中，传统的网络应用层安全边界发生了深刻演化。本实验紧扣谢希仁《计算机网络》（第8版）第7章关于应用层安全、报文完整性与访问控制的核心思想，针对 LLM 应用中“控制指令与数据载荷混淆”所引发的提示注入（Prompt Injection）安全威胁展开深入攻防实践。基于 FastAPI 搭建 LLM 问答服务，系统通过 OpenAI 兼容协议接入美团 LongCat 开放平台大模型 **`LongCat-2.5`**（`https://api.longcat.chat/openai/v1`）；构建了覆盖 4 类典型手法（直接指令覆盖、系统提示词窃取、角色扮演越狱、分隔符语法逃逸）的标准攻击数据集（21 条攻击 + 10 条良性对照）；设计并实现了包含输入过滤、指令与数据分离、输出审计的三层纵深防御护栏系统；完成了包含 5 组消融实验的量化评测体系。实验结果表明，在 `LongCat-2.5` 真实模型评测上，输入过滤层本地直接拦截 76.19% 的攻击（16/21），良性误拦截率维持 0.0%，端到端平均时延由 13521.93 ms 降至 11050.38 ms；同时结合离线弱对齐仿真模型验证了三层纵深护栏机制将基线攻破率从 23.81% 压制至 0.0% 的机理闭环。最后，报告深入剖析了 AI 防御及自动评测的局限性。

## 第一部分：教材原理复现（地基）

### 1.1 对应教材章节与经典安全原理
本实验对应教材**第 7 章“网络安全”**，特别是关于应用层通信面临的威胁机理（报文截获、伪造、篡改与应用注入攻击）。
- **指令与数据分离原则（冯·诺依曼同源困境）**：
  在计算机网络应用发展史上，SQL 注入、XSS、命令注入等经典漏洞的根本根源，皆在于**“控制信令（Control Instructions）与数据载荷（Data Payload）在语法解析层面未实现严格解耦”**。当不可信的用户输入被当做命令解释执行时，系统的安全策略即被击穿。
- **参数化与协议定界机制**：
  经典网络协议（如 HTTP、TCP、TLS）通过严格的头部格式（Header）与载荷体（Body）定界符，以及数据库访问中的预编译参数化查询（Parameterized Queries），从协议结构上确保“数据永远只是数据，不能逃逸为指令”。

### 1.2 经典 HTTP/Web 问答通信实现
为了验证基础应用层通信机制，实验使用 FastAPI 构建了标准 RESTful 问答服务，网络通信架构如下：
- **传输层与应用层协议**：基于 TCP/IP 栈上的 HTTP/1.1，采用 JSON 载荷封装请求与响应。
- **环境安全配置**：依据网络安全规范，系统 API Key 严格禁止硬编码，采用 `.env` 配置文件与系统环境变量注入（Environment Variable Management），防止代码提交造成的凭证泄露。

```text
[Client / 客户端]
       │
       ▼ (HTTP POST /api/chat - JSON Payload)
[FastAPI Web Server / 应用网关]
       │
       ▼ (HTTPS RESTful Call via LongCat OpenAI API: https://api.longcat.chat/openai/v1)
[LongCat-2.5 / 云端大模型引擎]
```

经测试，基础 HTTP 问答接口通信稳定，支持状态监控与标准 HTTP 状态码回传。

## 第二部分：AI 增强部分（核心护栏设计）

### 2.1 为什么需要 AI 应用层安全护栏？
在将大模型引入网络应用时，传统 Web 防火墙（WAF）主要针对固定签名的字符串注入，面对**具有开放语义和自然语言模糊性**的 Prompt Injection 攻击往往失效。用户可以通过自然语言伪装，诱导大模型违反开发者预置的系统规则（如泄露机密口令、执行越狱命令）。因此，必须在应用层构建一套多阶段纵深安全护栏（Defense-in-Depth Guardrails）。

### 2.2 攻击用例集构建（覆盖 4 大类主流手法）
本实验设计并实现了包含 21 条攻击样本与 10 条良性对照样本的测试集（`dataset/`）：
1. **直接指令覆盖 (Direct Instruction Override)**：通过强命令句式要求大模型放弃原有助教身份；
2. **系统提示词窃取 (System Prompt Leaking)**：诱导大模型复述、输出包含机密 Flag 的底层系统设定；
3. **角色扮演越狱 (Role-play Jailbreak)**：利用 DAN（Do Anything Now）、开发者模式或平行宇宙设定绕过合规限制；
4. **分隔符与语法逃逸 (Delimiter Hijacking)**：伪造 XML 闭合标签 `</user_data>` 或破折号分隔符，破坏上下文边界。

### 2.3 三层纵深防御方案实现
针对上述攻击手法，设计并落地了三层护栏管线（`defense/`）：

1. **第一层：输入层规则与模式过滤 (Input Filter)**
   - 部署正则签名库，对常见的越狱指令（如 `ignore previous instructions`、`DAN模式`、`CONFIDENTIAL_FLAG`、伪造闭合标签等）实施预检；
   - 命中恶意模式后，在请求触达大模型前即时返回 WAF 拦截响应，降低不必要的 LLM 计算开销。
2. **第二层：指令与数据分离加固 (Prompt Guard)**
   - **结构化标签隔离**：采用标准化 XML 标签 `<user_data>...</user_data>` 显式包裹用户输入；
   - **特殊字符转义**：对用户载荷中试图闭合标签的恶意字符进行 HTML 实体转义（如将 `</user_data>` 转为 `&lt;/user_data&gt;`），阻断语法逃逸；
   - **动态金丝雀探针 (Canary Token)**：每次会话动态生成单次有效的高熵金丝雀令牌（如 `CANARY_TOKEN_XXXX`）植入系统提示词中，并严令大模型保密。
3. **第三层：输出层内容安全审计 (Output Auditor)**
   - **金丝雀泄露侦测**：若输出包含 Canary Token，判定底层提示词发生严重泄露，强行熔断；
   - **敏感凭证检测**：拦截包含系统预置机密 Flag（`CONFIDENTIAL_FLAG`）的输出；
   - **越狱状态承认检测**：过滤带有“DAN模式已开启”、“指令覆盖成功”等失控状态表征的文本，兜底保障交付安全。

## 第三部分：AI 的局限性探讨（反思与边界）

实验不仅关注防御成功率，更依照验收核心原则对 AI 应用层防御的深层局限性展开剖析：

### 3.1 语义歧义性与莱斯定理的自然语言映射
- **规则过滤的不可完备性**：基于正则表达式的输入过滤器只能覆盖已知特征。攻击者可借助同义替换、多语言混合（如 Base64、小语种隐喻）轻松实施绕过；
- **自然语言的非形式化特质**：形式语言（如严格语法的编程语言）可以通过确定性有限状态机（DFA）或语法树完全判定，而自然语言语义边界是模糊的，不存在能够 100% 区分“正常学术探讨”与“恶意提示注入”的有限规则集合。

### 3.2 安全性（Safety）与实用性（Helpfulness）的博弈困境
- **过度防御与误拦截（Over-defense & False Positives）**：
  若进一步收紧输入正则规则，将包含“提示词”、“口令”、“规则”等词汇一律拦截，当学生正常询问“谢希仁教材第7章讲到的身份认证口令机制是什么”时，就会发生误拦截，严重损害服务可用性。

### 3.3 推理时延与 Token 成本开销
- **系统提示词膨胀**：指令与数据分离策略需要向 System Prompt 中追加防御规范、格式要求与 Canary 探针，增加了每次调用的输入 Token 长度；
- **时延阶跃**：若未来引入第二阶段轻量级 LLM 进行双重审计，将导致端到端响应时间成倍增加，在高并发网络服务中可能成为性能瓶颈。

## 四、 结论与实习总结

本项目成功复现了应用层提示注入攻击与防护的全生命周期，验证了将经典网络安全“纵深防御”与“控制-数据解耦”思想应用于 LLM 系统的有效性。实验成果包括可复现的自动化评测脚本、可视化科研图表、命令行交互演示平台及严格的环境变量安全规范，圆满达成了网络技术综合实习选题 6 的各项检查要点。
